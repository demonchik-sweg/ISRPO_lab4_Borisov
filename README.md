**Задача** — написать unit-тесты для библиотеки `geometric_lib`, созданной в лабораторной работе №1 (или №2), покрывающие все 4 фигуры: круг, квадрат, прямоугольник, треугольник.

## План тестирования

### 1. Цели и задачи тестирования

**Цели:**
- Проверить корректность работы функций вычисления площади и периметра для 4 геометрических фигур.
- Обеспечить автоматическую регрессионную проверку при дальнейших изменениях кода.
- Выявить возможные ошибки в реализациях.

**Задачи:**
- Разработать набор тестов для каждой функции, покрывающих типичные и краевые случаи.
- Организовать тесты в структуру, соответствующую стандартам `unittest`.
- Обеспечить возможность запуска всех тестов одной командой.
- Зафиксировать результаты тестирования.

### 2. Описание тестируемого продукта

**Название:** библиотека `geometric_lib`.

**Функциональность:**

| Модуль | Функции | Описание |
|---|---|---|
| `circle.py` | `area(r)`, `perimeter(r)` | Площадь и длина окружности радиуса `r` |
| `square.py` | `area(a)`, `perimeter(a)` | Площадь и периметр квадрата со стороной `a` |
| `rectangle.py` | `area(a, b)`, `perimeter(a, b)` | Площадь и периметр прямоугольника со сторонами `a`, `b` |
| `triangle.py` | `area(a, h)`, `perimeter(a, b, c)` | Площадь (по основанию и высоте) и периметр треугольника |

**Требования к продукту:**
- Все функции принимают неотрицательные числа.
- Возвращают корректный числовой результат.
- Для нулевых входов возвращают `0`.

### 3. Область тестирования

**Тестируется:**
- Все 8 функций (`area` и `perimeter` для каждой из 4 фигур).
- Поведение на нулевых аргументах.
- Поведение на единичных значениях.
- Поведение на типичных значениях.
- Поведение на дробных числах (для функций, возвращающих float).
- Поведение на больших числах.

**Не тестируется:**
- Вспомогательные функции (если есть).
- Импорты и структура проекта.
- Обработка некорректных входов (отрицательных чисел) — по заданию не требуется.
- Производительность.
- Безопасность.

### 4. Стратегия тестирования

**Подход:** функциональное unit-тестирование методом **чёрного ящика**.

**Обоснование:** исходный код фигур не изменяется, тесты пишутся как для внешнего продукта — проверяются только входы и выходы функций.

**Методы:**
- **Позитивное тестирование** — проверка корректных входов.
- **Граничное тестирование** — нули, единицы, минимальные значения.

**Техники:**
- **Эквивалентные классы** — входные данные разбиты на группы: нули, единичные, типичные, большие значения.
- **Анализ граничных значений** — особое внимание к `0` и `1`.

**Инструмент:** библиотека `unittest` из стандартной библиотеки Python 3.12.

**Организация тестов:**
- 4 файла: `test_circle.py`, `test_square.py`, `test_rectangle.py`, `test_triangle.py`.
- Размещены в отдельной папке `tests/`.
- Каждый файл содержит класс, наследуемый от `unittest.TestCase`.
- Имена методов начинаются с `test_`.

### 5. Критерии приёмки

Тестирование считается успешным, если:

- **Все тесты проходят** без ошибок (статус `OK`).
- Каждая из 8 функций покрыта **минимум 3 тестами** (нулевой, единичный, типичный случаи).
- Файлы тестов размещены в репозитории на GitHub.
- Факт добавления тестов отражён в истории коммитов.

Тестирование **считается завершённым** даже при наличии проваленных тестов — если по ним сделаны выводы о наличии дефектов в коде.

### 6. Ожидаемые результаты

- **Отчёт о запуске тестов** — вывод `unittest` с количеством пройденных и проваленных тестов.
- **Статус тестирования** — `OK` (все прошли) или `FAILED (failures=N)`.
- **Список дефектов** (если есть) — конкретные функции, входные данные, ожидаемый и полученный результат.
- **Метрики:**
  - Общее число тестов.
  - Число пройденных.
  - Число проваленных.
  - Время выполнения.

### 7. Актуальные результаты тестирования

**Команда запуска:**
- python -m unittest discover -s tests -t .
